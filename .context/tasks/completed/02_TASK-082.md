# TASK-082: Audit & Correct Utility Classes Site-Wide (Hbada Clone Redesign)

## Description
This task involves a site-wide audit of all React components to identify and replace any hardcoded color utility classes (e.g., `text-teal-500`, `bg-[#1DDBA6]`, `border-green-700`) with the newly defined semantic Tailwind classes (e.g., `bg-primary`, `text-destructive`, `border-accent`) that reflect the Hbada clone's black/white/red color palette established in TASK-081.

## Objectives
- Scan all `.tsx` files within `src/components/` and `src/pages/` for hardcoded color utility classes.
- Replace identified hardcoded color classes with appropriate semantic Tailwind utility classes (e.g., `primary`, `secondary`, `accent`, `destructive`, `foreground`, `background`, `neutral-*`).
- Ensure that the new semantic classes correctly render the intended colors from the updated global palette.
- Verify that interactive states (hover, focus, active) also use semantic classes and align with the new design.

## Steps
1.  **Identify Hardcoded Classes:**
    *   Use project-wide search tools (e.g., VS Code search) to find instances of common color utility patterns like `text-teal-`, `bg-teal-`, `border-teal-`, `text-green-`, `bg-green-`, `border-green-`.
    *   Also search for hexadecimal color codes used directly in Tailwind classes (e.g., `bg-[#1DDBA6]`, `text-[#28A76F]`).
2.  **Map to Semantic Classes:** For each identified hardcoded class, determine the appropriate semantic equivalent based on the new color palette defined in TASK-081 and the visual role of the element.
    *   Example: A teal button background `bg-teal-500` might become `bg-primary` (if primary is now red) or `bg-destructive` (if it's a destructive action button and red is the destructive color).
    *   Example: Teal text `text-teal-600` might become `text-primary` or `text-accent` depending on its function.
3.  **Replace Classes:** Systematically go through each component and replace the hardcoded classes with their semantic counterparts.
4.  **Test Components:** After modifying each component (or a group of components), visually inspect them in the browser to ensure:
    *   The correct new colors are applied.
    *   There are no unintended visual regressions.
    *   Interactive states (hover, focus, active) are styled correctly with semantic classes.
5.  **Prioritize Key Components:** Start with globally used components (Navbar, Footer) and then move to major page components (Homepage, Product Page, Cart Page) before tackling less critical or isolated components.
